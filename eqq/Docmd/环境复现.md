# eqq Docker 环境复现

这是任务 0.1 的开发环境配置：Python 3.12 容器、独立 Redis 和环境检查脚本。尚未实现对话应用。Python 依赖在 `requirements.txt` 固定版本；基础镜像使用系列标签，未来重建可能获得补丁更新，不承诺逐字节相同的镜像。

## 首次准备

安装并启动 Docker Desktop（或支持 Compose 的 Docker Engine）。在另一台机器复制仓库后，确保仓库根目录存在 `.env`，可从根目录 `.env.example` 复制后自行填入真实配置。不要提交 `.env`，不要将密钥直接写入 Compose 或 Dockerfile。

环境配置读取的是 `../.env`，不是 `eqq/.env`。模型配置通过 `env_file` 注入 Python 容器；Redis 连接由 Compose 设置为 `redis://redis:6379/0`。Redis 仅在 Compose 内部网络提供服务，没有向宿主机公开端口，不会占用本机 6379 端口。

以下命令均在仓库的 `eqq/` 目录执行：

```bash
cd /你的仓库路径/eqq
docker compose up -d --build
docker compose exec dev python scripts/check_environment.py
```

检查输出应显示 Python 版本、四个依赖可导入、必需配置已设置以及 Redis PING 成功；不会打印配置值，也不会消耗模型 API 额度。该检查只证明本地配置存在和环境可用，不证明 token 有效或接口可以调用，真实调用留给 A.2。

## 日常使用

```bash
# 进入 Python 开发容器
docker compose exec dev sh

# 查看 Python 或 Redis 版本
docker compose exec dev python --version
docker compose exec redis redis-cli --version

# 查看容器状态
docker compose ps

# 停止并移除容器、网络；保留 Redis 数据卷
docker compose down
```

`eqq/` 挂载到容器的 `/workspace/eqq`，在 IDE 修改的文件会同步到容器。依赖变更后重新运行 `docker compose up -d --build`；根目录 `.env` 变更后，用 `docker compose up -d --force-recreate dev` 重新注入配置。不要运行会输出完整环境变量的命令或无脱敏的 `docker compose config`，以免泄露 token。

## 数据与迁移

Redis 开启 AOF，数据保存在 `eqq_redis_data` 命名卷，普通 `down` 不删除数据。文件配置可以在其他机器重建环境，数据卷不会自动随仓库迁移；需要迁移会话数据时再单独设计导出/恢复步骤。

任务 0.1 验证结束后会停止容器，学习时使用上述启动命令即可继续。此阶段只验证 Redis 连接，不实施会话读写、TTL 或摘要等后续任务。
